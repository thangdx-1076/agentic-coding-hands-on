# C19 Test Bug Fix: Exhaustive Scroll to End

## Fix Summary

Fixed `[C19] Scrolling to end of data: no sentinel, no error` which failed locally due to a single `scrollBy()` call being insufficient to exhaust a 184-item feed.

## Change

**Before:**
```ts
await page.evaluate(() => {
  window.scrollBy(0, document.body.scrollHeight);
});
```

**After:**
```ts
for (let i = 0; i < 50; i++) {
  const sentinel = page.locator("[data-testid=kudos-feed-sentinel]");
  const sentinelCount = await sentinel.count();

  // If sentinel is unmounted from DOM, we've reached the end
  // eslint-disable-next-line playwright/no-conditional-in-test
  if (sentinelCount === 0) {
    break;
  }

  // Scroll sentinel into view to trigger intersection observer
  await sentinel.scrollIntoViewIfNeeded();
  
  // Wait for data to load
  await page.waitForTimeout(300);
}

// Verify sentinel has been unmounted
const sentinel = page.locator("[data-testid=kudos-feed-sentinel]");
await expect(sentinel).toHaveCount(0);
```

## Why It's Strictly Stronger

- **Before:** Single scroll missed pagination boundaries; sentinel still visible → poll timeout → RED (was a hidden pre-existing bug)
- **After:** Exhaustive loop repeatedly scrolls + waits for loading until sentinel unmounts entirely from DOM (component's real signal that `hasMore=false`)
- **Bound:** 50 iterations is generous for ~184 items; loop breaks early when end is reached
- **Assertion unchanged:** Final `expect(sentinel).toHaveCount(0)` stays, confirming we reached true end of data
- **No weakening:** Test still proves the sentinel disappears and no empty state occurs
